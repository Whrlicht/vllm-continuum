14. 代码梳理
第一层：入口和路由

先读这个：

examples/online_serving/disaggregated_serving_p2p_nccl_xpyd/
    run_disagg_p2p_nccl_xpyd_prod.sh
    disagg_proxy_p2p_nccl_xpyd_prod.py

看清楚：

启动了几个 P、几个 D
每个 worker 的 HTTP/KV 端口怎么分配
proxy 怎么选 P/D
kv_transfer_params 怎么塞进请求

核心问题：一个请求为什么先到 P，再到 D。

第二层：P/D KV 迁移

然后读：

vllm/distributed/kv_transfer/kv_connector/v1/p2p/
    p2p_connector.py
    p2p_nccl_connector.py
    p2p_engine_selector.py
    p2p_hccl_engine.py
    hccl_wrapper.py

重点顺序：

p2p_connector.py
    -> 选择 NCCL 还是 HCCL

p2p_nccl_connector.py
    -> vLLM 调度器和 KV connector 的主逻辑

p2p_hccl_engine.py
    -> Ascend 上真正做 HCCL 迁移

核心问题：D 怎么向 P 拉 KV，P 怎么把 block 发给 D。

第三层：C3 round-kv

再读：

vllm/v1/core/sched/licht_v3/
    round_kv_store.py
    arena_lru_store.py
    ssd_tier.py
    ssd_writer_process.py
    ssd_stage_ring.py

顺序：

round_kv_store.py
    -> D 结束后怎么 store，P 下一轮怎么 load

arena_lru_store.py
    -> CPU arena 怎么管理、去重、LRU、驱逐

ssd_tier.py
    -> CPU arena 怎么降到 SSD，SSD 怎么 promote 回来

ssd_writer_process.py
    -> 独立写进程怎么 drain ring

ssd_stage_ring.py
    -> worker 到 writer 的共享内存队列

核心问题：
D NPU -> CPU arena -> SSD -> CPU arena -> P NPU 是怎么走的。

第四层：预测式 staging

最后读：

vllm/v1/core/sched/licht_v3/
    decode_manager.py
    predictors.py
    shadow_scheduler.py
    step_event.py

顺序：

decode_manager.py
    -> tool call 结束/回访预测入口

predictors.py
    -> tool 时间预测模型怎么加载

shadow_scheduler.py
    -> 预测回来后排队多久、什么时候该 staging

step_event.py
    -> P 侧调度状态怎么发布给 D 侧 shadow scheduler

核心问题：C3 为什么不是“等请求回来再搬”，而是提前算 deadline。

最小阅读路线

如果你只想先读懂主链，按这个顺序：

1. disagg_proxy_p2p_nccl_xpyd_prod.py
2. run_disagg_p2p_nccl_xpyd_prod.sh
3. p2p_nccl_connector.py
4. p2p_hccl_engine.py
5. round_kv_store.py
6. arena_lru_store.py
7. ssd_tier.py
8. decode_manager.py
9. shadow_scheduler.py

读的时候只抓 5 个动作：

route       请求分给哪个 P/D
prefill     P 怎么产出 KV
migrate     P KV 怎么给 D
store       D KV 怎么沉到 CPU/SSD
promote     下一轮怎么从 SSD/CPU 回到 P
